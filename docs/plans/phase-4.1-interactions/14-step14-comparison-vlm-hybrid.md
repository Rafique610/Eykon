# Phase 4.1 Step 14 — Comparison with the VLM Path and a Hybrid

## What

The comparison the supervisor asked for, on the same sessions and the same
metrics:

| Config | Extraction | Language model used |
|---|---|---|
| C | Cheap path only (path C, this phase) | none |
| V | VLM path (Phase 4 Step 09 path V) on the frames the cascade passes | VLM |
| V-trig | VLM only on frames where the hand gate fired | VLM (fewer calls) |
| H | Hybrid: path C, plus VLM called only when path C is `uncertain` or the place is unknown | VLM on demand |

Metrics (from Step 12): event precision / recall per size, identity accuracy,
place accuracy, downstream "where is X" lookup accuracy, plus cost: model
calls per hour by type, compute per minute, peak RAM (laptop), and phone cost
from Step 15 when available.

If the phase scope is "negative result" (Step 01), this step instead writes
the comparison from the Probe B data only.

## Why

- This table is the object-side evidence for Gate 3 (roadmap v2 §6: is the LLM
  needed, and for which question types?). Phase 5.2 uses it as the object
  rows of the L0–L3 comparison.
- The hybrid tests a practical middle ground: most of the time cheap, VLM only
  when the cheap path is unsure. If it gets most of V's accuracy at a fraction
  of the cost, that is a strong design result.

## How to implement

1. Run all four configurations on the tuning and held-out sessions with the
   frozen settings; V and V-trig use the Phase 4 frozen path V settings.
2. Hybrid rule: call the VLM on the release frame (and one frame before) when
   identity is `uncertain` or place is `null`; VLM answers are converted to
   slot records and merged (`refines`).
3. Tables per config × metric with intervals; cost table; a plot of accuracy
   vs VLM calls per hour for all four.
4. Paired comparison per event (which config gets it right), small 2×2 tables
   for C vs V and H vs V.
5. Written conclusion: which configuration is best for which object size and
   budget, including "the VLM is needed for small objects" if that is what
   the data shows.

## Open decisions

- **Hybrid trigger.** Options: (a) uncertainty only; (b) uncertainty or
  unknown place (draft); (c) every put-down — more accurate places, more
  calls. Cost decides.

## You test this

1. Look at the accuracy vs calls-per-hour plot. Which point would you choose
   for your own phone?
2. Look at 10 events where C and V disagree; who was right?

## How this number could be lying

- The VLM path's event rule may suit captions less well than path C's rule
  suits hands (noted in Phase 3.1 Step 19); the VLM config uses the Phase 4
  Step 10 segmenter's events where possible, and the rule used is stated.
- Laptop costs favour the VLM less than phone costs do (the gap grows on
  phones); phone costs from Step 15 are added before conclusions are final.
