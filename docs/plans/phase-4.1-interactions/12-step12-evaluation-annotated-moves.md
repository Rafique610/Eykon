# Phase 4.1 Step 12 — Evaluation on Annotated Moves (Main 4.1 Results)

## What

The main results table for this phase, measured once on tuning sessions and
once on **held-out** sessions (frozen configuration):

- event precision and recall for `pick_up`/`take` and `put_down`/`place`,
  per object size (small / medium / large), per visibility (visible / partly
  / not visible), per lighting, per mount, scripted vs unscripted,
- object identity accuracy among detected events,
- place accuracy for put-downs (room level and surface level),
- downstream: accuracy of "where is X now / at time t" answered directly
  from the path C records replayed in order (a simple last-known-state
  lookup, no language model) — the first L0 answer numbers for objects,
- cost per minute of video (laptop) and from Step 15 (phones),
- all rates with 95 % Wilson intervals; worst session reported.

## Why

- Exit criterion of the phase (roadmap v2: "precision and recall reported per
  object size").
- Held-out results in new places are the only numbers that count for claims;
  tuning numbers show how much was overfitted.
- The downstream lookup links event accuracy to what users actually ask, and
  feeds Phase 5.2's L0 configuration.

## How to implement

1. **Freeze** the configuration (all thresholds, model hashes) into
   `docs/results/phase-4.1/frozen-config.json` with a hash before opening the
   held-out sessions.
2. **Held-out QA**: object-category questions for the held-out sessions
   written before the run (shared with Phase 4 Step 12; coordinate so they
   are written once).
3. **Evaluation script** `src/benchmarks/interaction_eval.py`, reusing the
   event matcher from Phase 3.1 Step 19 (`src/probes/event_match.py`) —
   moved to a shared place if needed.
4. **Run** on tuning and held-out sessions; tables generated by script.
5. **Generalisation gap** table: tuning vs held-out for every metric.
6. **Compare with the Step 01 targets**; verdict written plainly.

## Open decisions

- **What counts as "visible".** The annotation `visibility` flag is used; if
  annotators disagree (Phase 3.1 Step 10 agreement), report with both
  annotators' flags on the double-annotated session.
- **Time tolerance**: inherited from Phase 3.1 (±2 s draft, adjusted to human
  agreement).

## You test this

1. Before the held-out run, write down your guess for small-object recall.
   Compare with the result.
2. Use the debug viewer on one held-out session and ask yourself five "where
   is X" questions; compare your memory with the lookup answers.

## How this number could be lying

- Held-out sessions are still recorded by the same person with the same
  objects; they test new places, not new users.
- Not-visible events are impossible for any camera; including them in recall
  is honest about user experience, excluding them is fair to the method.
  Both are reported.
- Downstream lookup accuracy depends on the asked-at times chosen in QA; the
  distribution of asked-at times is reported.
